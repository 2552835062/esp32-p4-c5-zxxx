# music_agent — 网易云远控代理（歌词版）

跑在 Windows 电脑上的 Python 小服务，把网易云音乐正在播放的歌交给 ESP32
歌词屏显示，并转发板子的切歌/播放指令。板端只需在 menuconfig 里填好同一个局域网的 WiFi，
之后靠 UDP 广播自动发现电脑。

曲目信息取自网易云主窗口标题（"歌名 - 歌手"），播放/暂停状态取自系统媒体
会话（SMTC），控制指令用 Windows 系统媒体键（等价于键盘上的多媒体键），不模拟点击网易云窗口。之所以不用
SMTC 读曲目：实测网易云 3.x 的媒体属性是**冻结**的（一直报同一首歌），切歌
API 也不工作。

## 安装与启动

```powershell
cd tools\music_agent
pip install -r requirements.txt
python music_agent.py          # 默认端口 8777
python music_agent.py --port 9000

# 或者直接双击 run_agent.bat：会打开一个可见的 CMD 窗口，
# 日志直接显示在窗口里；关闭窗口即可停止代理。
```

首次启动 Windows 防火墙会弹窗，选择"允许访问"（需要放行 UDP 9878 和 TCP 端口）。

## 要求

- 网易云音乐 Windows 客户端处于登录且**正在运行**（代理按窗口标题取曲目，主窗口最小化到托盘也可以）。
- 电脑和板子连同一个局域网（同一网段，路由器未开 AP 隔离）。
- Pillow 用于生成封面和背景小图；未安装时状态与控制仍可用，只是没有封面。
- 歌词：按"歌名+歌手+时长"搜网易云公开接口取 LRC，按播放进度把当前句放进 `/state`；
  搜不到或网络失败时该字段为空，板子显示"暂无歌词"。

## 常见问题

**只打开网易云、板子没反应？** 正常——网易云不会主动通知板子。板子只认本代理：
必须先 `python music_agent.py` 并保持运行（首次运行允许防火墙），板子会在 2 秒内
收到广播并自动连上，之后网易云一放歌状态就会过去，不需要其他任何操作。
如果代理已运行仍连不上，检查板子和电脑是否在同一网段（代理启动时会打印本机 IP）。

## 接口

| 路径 | 说明 |
| --- | --- |
| `GET /state` | 播放状态 JSON：标题/歌手/专辑/进度/是否播放/封面哈希/当前歌词行 |
| `GET /lyrics?h=<hash>` | 整首 LRC 文本（板端自己解析并滚动显示） |
| `GET /art_rgb565?h=<hash>` | 240x240 RGB565 小端序封面（板端直接显示，不需要 JPEG 解码） |
| `POST /cmd` | `{"action":"play_pause"\|"next"\|"prev"}`；成功返回 `{"ok":true,"via":"mediakey"}`，走 SMTC 时 `via` 为 `"smtc"` |

板端发现机制：每 2 秒广播 `MUSICAGENT|<ip>|<port>` 到 UDP 9878；
8 秒收不到广播，板子自动转入演示模式。

## 歌词与进度是怎么来的

- **歌词**：按"标题+歌手+时长"在网易云搜索里打分挑原曲（避免挑到翻唱），
  取 `/api/song/lyric` 的 LRC 交给板端；失败 30 秒后自动重试。外语歌同时取
  翻译（tlyric），按时间戳对齐后与原文一起下发，板端显示为上下两行。
- **曲目**：读网易云主窗口标题（"歌名 - 歌手"），过滤"网易云音乐/桌面歌词/迷你播放器"
  这类页面名。窗口最小化到托盘时也能读到。
- **控制**（全部走 Windows 系统层，不模拟点击网易云窗口）：
  - `next` / `prev`：全局媒体键 `VK_MEDIA_NEXT_TRACK` / `VK_MEDIA_PREV_TRACK`
    （`keybd_event`），由 Windows 路由给当前媒体应用；SMTC 的 `try_skip_*` 作为回退。
  - `play_pause`：优先 SMTC 的 play/pause；当前机器的 SMTC 会话可能为 0
    （网易云最小化到托盘或版本不注册），此时发全局 `VK_MEDIA_PLAY_PAUSE`。
  - 没有 SMTC 时无法校验播放状态，代理按最近一次命令维护假定状态；在网易云界面里
    直接暂停/播放后，`/state` 的 `playing` 可能短暂不同步。
- **进度**：网易云的 SMTC *不给时间线*（`get_timeline_properties()` 的 position/end_time 恒为 0、
  last_updated 停在 1601 年），调试端口里也没有 `<audio>` 元素（.NET 原生播放），
  所以进度由代理的**本地时钟**推算：切歌归零、暂停冻结、播放累加、单曲循环按
  "超出时长 3 秒"绕回。**在电脑上拖动进度条无法感知**，屏幕进度会从拖之前的位置继续走。
- **播放状态**：winrt 的 `playback_status` 枚举 `str()` 出来是数字（"4" 才是播放中），
  不能用字符串判断。
- **依赖**：`aiohttp` + `Pillow`（下载/缩放封面）+ `pycaw`（Windows 音频会话峰值，
  判断网易云是否真的在播放/暂停）；没有任何截图或 OCR 依赖。

## 踩坑（都是实测踩出来的）

- 网易云的 SMTC 媒体属性是**冻结**的（一直报上一首），只有 `playback_status` 可信；
  曲目必须读窗口标题。
- 当前机器上 SMTC 会话可能为 0（网易云最小化到托盘、或版本不注册媒体会话）。
  全局媒体键仍能切歌/暂停，但无法校验播放状态；代理用最近一次命令的假定状态
  维护 `/state`。
- 全局媒体键是系统级输入，不需要管理员权限；如果网易云以管理员身份运行而代理不是，
  Windows UIPI 可能拦截合成输入，此时让两者权限一致即可。

## 验证

电脑上用任意浏览器打开 `http://127.0.0.1:8777/state`，播放一首歌应能看到
JSON 里的标题和进度变化；`GET /art?h=<state 里的 art_hash>` 应返回封面图。

代理单元测试（不需要 Windows/网易云/WinRT）：

```bash
cd <仓库根>
python tests\music_agent_test.py
```


## 本工程的用法

本项目 `esp32-p4-c5-zxxx` 只使用 `/state`、`/lyrics`、`/cmd` 三个接口：

- 板端每秒拉一次 `/state`，取标题、歌手、播放状态、进度和曲目哈希；
- 曲目哈希变化时拉一次 `/lyrics?h=<hash>`，板端自己解析标准 LRC 并滚动；
- 底部三个按钮通过 `POST /cmd` 发送 `play_pause` / `next` / `prev`。

封面接口保持可用，但歌词版界面不会请求它，Pillow 只是保留兼容。
